# 港股沽空监控（hk_short 模块）设计文档

日期：2026-09-21
状态：已与用户确认定稿

## 1. 背景与目标

现有 `flow_dashboard` 是 A股资金流单页监控（ETF资金流/两融/衍生品基差/月度）。本设计在其基础上新增**港股沽空监控**模块。

核心诉求（用户原话）："每天拉新数据，给我一个港股市场空头状态的结论，数据也可以展示一下。"

分析方法论遵循用户提供的沽空分析规范，核心原则：

- **Gross Short Flow ≠ Net Short Position Change**：每日沽空成交额是流量，不能直接推断净空仓变化
- **存量定方向，流量看强度，价格看结果，成交量看参与度**
- 判断优先级：周度未平仓淡仓Δ → 沽空额异常 → SSR 历史分位 → 价格 → 量 → ETF/对冲干扰
- 状态结论由**纯规则引擎**生成（确定性、可测试），不使用 LLM 生成结论

## 2. 盘面范围

- **市场层面**：全市场汇总指标 + 状态结论（本模块的核心产出）
- **个股层面**：固定 watch list 的逐日明细表 + 当日沽空额 TOP20 榜单
- **不做**：全市场逐股深度跟踪、交易建议

## 3. 前端方案：同一 HTML 内 tab 分页

`theme.py` 的 `build_html_skeleton()` 增加 `tabs` 参数：

- 顶部一级导航：「A股资金流 | 港股沽空」，默认停在 A股
- 每个 tab 一个容器，内含各自的 section-nav 锚点导航
- ~15 行原生 JS 切换，URL 记住当前 tab，刷新不跳回
- A股页现有 DOM 与行为不变，只是包进 tab 容器
- 任一侧数据缺失：对应 tab 显示"数据待更新"横幅，不影响另一 tab

选择该方案（而非独立 HTML / 长滚动追加板块）的理由：渲染从 parquet 缓存确定性重放，港股数据源故障不会拖垮 A股页发布；单一 URL 与发布产物；为后续第三个市场留扩展口。

## 4. 港股 tab 页面结构（自上而下）

### 4.1 空头状态结论卡（最重要，置顶）

- 一句话市场结论，规则引擎输出，枚举值：
  - 空头净加仓迹象明显 / 空头净回补迹象明显 / 沽空活跃但净仓变化有限 / 多空分歧扩大 / 暂时无法确认
  - SFC 最新周数据未覆盖时，统一加"·SFC待确认"后缀，表述降级为"迹象"
- 三个副指标：今日全市场沽空额（vs 20日均倍数）、市场加权 SSR（60日分位）、最新 SFC 周度淡仓环比
- ETF 沽空占比过高时（阈值见 §6），结论下方注明"总沽空增加或主要来自指数对冲，不宜直接解读为个股看空增强"

### 4.2 市场总览图

- 总沽空额 + 市场加权 SSR 双轴时序，叠加恒指/恒生科技走势
- 目的：一眼看出"沽空放大时价格怎么走"

### 4.3 个股逐日明细表（列格式与用户示例一致）

列：交易日期｜卖空股数｜卖空金额｜未平仓卖空期末值·股数｜未平仓卖空期末值·金额｜收盘价｜涨跌幅%｜成交量｜成交额｜卖空股数/成交量%（SSR）｜期末未平仓卖空股数/总股本%

- 展示 watch list 每只股票最近 ~20 个交易日
- 未平仓两列**只在 SFC 周度报告日有值**（稀疏列，与示例一致）
- 每张表上方标注该股状态标签

## 5. 数据链路

新增 `src/flow_dashboard/data/hk_short/` 子包，loader 模式照抄现有（读 parquet 缓存 → 拉增量 → merge → 写回 → PIT 过滤）。缓存落 `data/hk_short/cache/*.parquet`。

| 数据 | 来源 | 频率 | 滞后 |
|---|---|---|---|
| 个股逐日卖空成交 + 日线（价、量、额、总股本） | 东方财富港股"卖空"数据（HTTP 抓取；akshare 封装可作备选实现） | 每交易日 | T日盘后 |
| 全市场逐证券每日卖空额（TOP榜、SSR 分位的历史基础） | HKEX 官网逐日报告或东财沽空排行页（实现期验证取其一） | 每交易日 | T日盘后 |
| 个股周度未平仓淡仓（SFC 汇总口径，含股数/金额） | 优先东财（已整合）；若覆盖不全，兜底抓 SFC 官网周度 Excel | 每周（截至周五） | ~3-7天 |
| 市场总沽空额、主板总成交额（算加权 SSR） | HKEX 官方汇总 | 每交易日 | T日盘后 |
| 恒指、恒生科技指数日线 | 行情源（东财/akshare） | 每交易日 | T日盘后 |

要点：

- **个股 SSR 只对 watch list + TOP榜标的计算**：卖空历史来自全市场逐证券日频数据集（天然积累所有股票历史），成交额只对 watch list + 当日 TOP20 按需逐股查询，不拉全市场行情
- 每个面板标注"数据截至"日期
- 未平仓周环比 = 最新报告日 vs 上一报告日；中间日频数据不参与淡仓比较
- 抓取失败重试后仍失败：保留缓存旧数据 + 页面挂"数据待更新"，不阻塞发布

## 6. 指标与状态引擎（`indicators/hk_short*.py`，纯规则）

### 6.1 指标

- `SSR_t` = 卖空额 / 总成交额
- 沽空强度 = 当日卖空额 / 20日平均卖空额
- SSR 60日历史分位（历史不足60日时用可得历史并标注）
- 成交额 20日均值倍数
- SFC 淡仓股数周环比 Δ、3-4 周趋势（优先用股数，不用市值）

### 6.2 市场状态判断顺序（硬编码）

1. SFC 周度淡仓股数 Δ（若最新周未公布 → 结论降级"·SFC待确认"）
2. 本周累计沽空额是否异常（vs 历史均值）
3. SSR 是否处于历史高分位
4. 价格方向（恒指/恒生科技）
5. 成交量是否放大
6. ETF 沽空占比检查：watch list ETF + 全市场 ETF 沽空额占比超过阈值（初值 30%，可配）时触发"指数对冲"提示

### 6.3 状态矩阵（市场与个股共用逻辑，分别输出）

| 状态 | 组合 |
|---|---|
| 空头净加仓迹象明显 | 淡仓↑ + 沽空额>历史均值 + SSR高分位 + 价跌 + 量放大 |
| 多空分歧扩大 | 淡仓↑ + 价涨（空头逆势加仓） |
| 空头净回补迹象明显 | 淡仓↓ + 价涨 + 量放大（沽空额高也可并存，注明） |
| 沽空活跃但净仓变化有限 | 沽空额高 + SSR高 + 淡仓Δ≈0 |
| （跌但空仓减）| 价跌 + 淡仓↓ → 注明"下跌压力或来自长仓卖盘而非新增空头" |
| 暂时无法确认 | 证据互相矛盾或不足 |

严格模式：只有证据非常强时才使用 "short squeeze" 表述，且注明是行为特征判断。阈值集中在 config 常量，便于校准。

## 7. 调度与发布

- 新 launchd plist `com.ygr.hk-short.eod`：每交易日 18:45（北京=香港时间）
  - 拉 HKEX 汇总 + 东财个股 + SFC（有新周报则抓）→ 整页重渲染 → 原子替换 `latest.html`
- A股 19:30 runner 不动；它重渲染时从 parquet 缓存把港股 tab 一起带上
- 港股休市日（A股开市）：runner 照跑，数据无增量即跳过渲染

## 8. 测试

- 状态引擎单测：§6.3 每个状态构造合成数据用例；SFC 缺失降级；ETF 干扰场景
- 指标边界：除零、历史不足60日、次新股
- loader 增量合并与 PIT 过滤测试（仿现有 test 模式）
- 真实抓取冒烟测试挂 `@live` 标记

## 9. 非目标

- 不做 LLM 生成的评论文字
- 不做全市场逐股跟踪、不做交易建议
- 不做盘中实时沽空监控（只做日频盘后）
